# Twitch Scraper — Исчерпывающая Техническая Документация (v2.0)

## 1. Обзор и назначение расширения

**Twitch Scraper** — это браузерное расширение (Google Chrome Manifest V3), предназначенное для извлечения данных о прямых трансляциях из любой категории на сайте Twitch (например, `twitch.tv/directory/category/minecraft`). 

Оно обходит защиту Twitch (CORS, Integrity-токены), перехватывая сетевые заголовки легальной пользовательской сессии, и самостоятельно выполняет серию запросов к недокументированному GraphQL (GQL) API Twitch. Собранные данные (основная информация о стриме, социальные сети и баннеры-панели под стримом) агрегируются и выгружаются пользователю в форматах `JSON` или `Markdown`.

---

## 2. Архитектура и структура файлов

Расширение спроектировано так, чтобы перенести всю тяжелую работу в изолированный фоновый процесс, не перегружая страницу Twitch, и обходить ограничения на кросс-доменные запросы.

| Файл | Описание |
|------|----------|
| `manifest.json` | Манифест V3. Объявляет разрешения: `webRequest` (для пассивного перехвата заголовков), `storage` (для сохранения состояния и данных), `scripting` (для внедрения скрипта скачивания), и доступ к хостам `*.twitch.tv` и `gql.twitch.tv`. |
| `background.js` | Основной движок (Service Worker). Выполняет всю бизнес-логику: перехватывает заголовки, осуществляет GQL-запросы, обходит баги пагинации Twitch, собирает соц. сети и панели батчами, управляет машиной состояний (пауза/отмена) и сохраняет промежуточные результаты в `chrome.storage.local`. |
| `popup.html` | Разметка пользовательского интерфейса (меню). Включает настройки фильтрации, переключатели языков, лимиты, выбор формата экспорта, систему отображения прогресса, а также панель дебаг-логирования. |
| `popup.js` | Логика интерфейса. Отправляет сообщения в `background.js` (`start_collection`, `stop_collection`, `resume_enrich`, `download_last_data` и др.) и реактивно обновляет UI (прогресс-бары, статус-пилюли) при получении сообщений `state_update` от Service Worker'а. |
| `content.js` | Минимальный Content Script. Исторически он делал запросы, но в версии 2.0 он оставлен только как безопасная точка инъекции: `background.js` через API `scripting` выполняет функцию `triggerDownload` внутри контекста страницы Twitch, чтобы сгенерировать `Blob` и инициировать скачивание файла. |

## 3. Перехват заголовков и обход защиты Twitch

### 3.1 Зачем нужен перехват?
GQL API Twitch (`gql.twitch.tv/gql`) защищено от автоматических скриптов системой **Integrity Check**. Каждый запрос требует заголовок `Client-Integrity` — токен, криптографически подписанный обфусцированным скриптом Twitch с использованием фингерпринта браузера пользователя. Расширение не может сгенерировать его самостоятельно.

### 3.2 Пассивный перехват (`webRequest`)
В `background.js` используется слушатель `chrome.webRequest.onSendHeaders`. Когда сам сайт Twitch (открытый во вкладке) делает легитимный GQL-запрос для отрисовки интерфейса, расширение "на лету" перехватывает следующие отправляемые заголовки:
- `Client-Id`
- `Client-Integrity`
- `Authorization`
- `X-Device-Id`
- `Client-Version`
- `Client-Session-Id`

### 3.3 Хранение и нормализация
Перехваченные заголовки сохраняются в `chrome.storage.local`. Поскольку JS-объекты чувствительны к регистру, в ранних версиях возникала ошибка `400 Bad Request` из-за дубликатов (например, `Client-ID` и `Client-Id`). 
В версии 2.0 используется жесткая маска нормализации (`HEADER_KEY_MAP`). Заголовки всегда приводятся к стандартному регистру (Pascal-Kebab-Case), а дубликаты удаляются. Функция `ensureHeadersLoaded()` гарантирует, что расширение всегда использует самые свежие рабочие токены. Если токен истек, расширение выдает ошибку, прося пользователя просто нажать `F5` на вкладке Twitch для захвата нового токена.

## 4. Сбор трансляций: GQL API и особенности

Сбор запускается отправкой сообщения `start_collection`. `background.js` определяет `slug` категории из URL открытой вкладки и начинает цикл запросов `DirectoryPageGame`.

### 4.1 Поиск по Slug
Запрос формируется с использованием аргумента `game(slug: $slug)`, а не `game(name: $slug)`. Это критически важно, так как поиск по имени (Name) не работает для игр со сложными названиями и спецсимволами, тогда как `slug` всегда точно идентифицирует директорию.

### 4.2 Особенность фильтрации языков
Если пользователь выбрал фильтр «🌐 Все языки», расширение передает параметр `broadcasterLanguages: []` (пустой массив). Это заставляет Twitch вернуть трансляции на абсолютно всех языках. При выборе конкретных языков (например, `RU`, `EN`), массив заполняется их кодами.

### 4.3 Баг Twitch с пагинацией (VIEWER_COUNT_ASC) и Сортировка
Twitch имеет баг в своей базе данных:
- При сортировке «По возрастанию» (`VIEWER_COUNT_ASC`) база данных генерирует нестабильные курсоры. В результате выдача зацикливается, дублируя мелкие стримы.
- Когда доходит до стримов с 0 зрителей, Twitch в качестве курсора кодирует Unix timestamp времени начала стрима (например, `s = 1781455831`). При запросе следующей страницы Twitch пытается найти трансляцию, у которой `viewersCount > 1.78 млрд`, и возвращает пустой список. Сбор обрывается.

**Решение в расширении (v2.0):** 
Если пользователь запускает сбор **"Без лимита"** (собрать всю категорию), расширение игнорирует настройку интерфейса на сервере и _всегда_ делает запросы с параметром `VIEWER_COUNT` (по убыванию). Это гарантирует стабильную, быструю серверную пагинацию без обрывов. Направление сортировки, которое выбрал пользователь, применяется **локально** в памяти прямо перед скачиванием файла.

### 4.4 Защита от зацикливания и Rate Limiting
Цикл сбора содержит задержку `150мс` между страницами. Если Twitch завис и возвращает один и тот же `cursor` и `id` последнего стрима на нескольких страницах подряд, расширение детектирует это и прерывает цикл.

### 4.5 Парсинг приватных (Sub-Only) трансляций
Интерфейс предоставляет настройку «Включать приватные». Если она активна, в параметры GraphQL-запроса добавляется флаг `includeRestricted: [SUB_ONLY_LIVE]`. Это заставляет Twitch отдавать скрытые трансляции, просмотр которых доступен только для платных подписчиков (сабов) данного канала.

## 5. Структуры запросов и ответов (Спецификация GQL)

Расширение взаимодействует с эндпоинтом `https://gql.twitch.tv/gql` методом `POST`. Тело запроса всегда отправляется в формате JSON и содержит поля `query` (или `operationName` для сохраненных запросов) и `variables`.

### 5.1 Основной запрос каталога (DirectoryPageGame)
Используется для получения списка трансляций.

**Запрос (Payload):**
```json
{
  "query": "query DirectoryPageGame($slug: String!, $cursor: Cursor) { game(slug: $slug) { streams(first: 100, after: $cursor, options: { sort: VIEWER_COUNT, broadcasterLanguages: [\"RU\"], recommendationsContext: { platform: \"web\" }, systemFilters: [] }) { pageInfo { hasNextPage } edges { cursor node { id title viewersCount broadcaster { id login displayName description followers { totalCount } } freeformTags { name } game { name displayName } } } } } }",
  "variables": {
    "slug": "minecraft",
    "cursor": null
  }
}
```

**Ответ (Response):**
Возвращается глубоковложенный JSON. Данные лежат в `data.game.streams.edges`. Каждое "ребро" (edge) содержит `cursor` (обязателен для запроса следующей страницы) и `node` (информацию о самом стриме).
```json
{
  "data": {
    "game": {
      "streams": {
        "pageInfo": { "hasNextPage": true },
        "edges": [
          {
            "cursor": "eyJzIjowLjM0Njg1OTYxMDAyMTc4MDIsImQiOmZhbHNlLCJ0Ijp0cnVlfQ==",
            "node": {
              "id": "51234567890",
              "title": "Утренний стрим",
              "viewersCount": 15400,
              "broadcaster": {
                "id": "12345678",
                "login": "streamer_login",
                "displayName": "Стример",
                "description": "Описание канала...",
                "followers": { "totalCount": 250000 }
              },
              "freeformTags": [ { "name": "Русский" }, { "name": "Выживание" } ],
              "game": { "name": "Minecraft", "displayName": "Minecraft" }
            }
          }
        ]
      }
    }
  }
}
```

### 5.2 Запрос социальных сетей (GetChannelSocial)
Twitch не поддерживает батчинг соцсетей по умолчанию, поэтому расширение отправляет массив запросов (GraphQL Batching).

**Запрос (Батч из массива объектов):**
```json
[
  {
    "query": "query GetChannelSocial($login: String!) { user(login: $login) { login channel { socialMedias { name title url } } } }",
    "variables": { "login": "streamer_login_1" }
  },
  {
    "query": "query GetChannelSocial($login: String!) { user(login: $login) { login channel { socialMedias { name title url } } } }",
    "variables": { "login": "streamer_login_2" }
  }
]
```

**Ответ:** Массив ответов. Поля соцсетей лежат в `data.user.channel.socialMedias`.
```json
[
  {
    "data": {
      "user": {
        "login": "streamer_login_1",
        "channel": {
          "socialMedias": [
            { "name": "youtube", "title": "YouTube", "url": "https://youtube.com/..." },
            { "name": "telegram", "title": "ТГ Канал", "url": "https://t.me/..." }
          ]
        }
      }
    }
  }
]
```

### 5.3 Запрос панелей канала (ChannelPanels)
Используется встроенный в Twitch `operationName` и хэш `persistedQuery` вместо отправки тела самого запроса текстом. Отправляется массив для батчинга по `id` (уникальный идентификатор канала, а не логин).

**Запрос:**
```json
[
  {
    "operationName": "ChannelPanels",
    "variables": { "id": "12345678" },
    "extensions": {
      "persistedQuery": {
        "version": 1,
        "sha256Hash": "06d5b518ba3b016ebe62000151c9a81f162f2a1430eb1cf9ad0678ba56d0a768"
      }
    }
  }
]
```

**Ответ:** Данные лежат в `data.user.panels`.
```json
[
  {
    "data": {
      "user": {
        "id": "12345678",
        "panels": [
          {
            "__typename": "DefaultPanel",
            "title": "Правила",
            "linkURL": "https://vk.com/...",
            "description": "Не ругаться в чате.",
            "altText": "Баннер с правилами"
          }
        ]
      }
    }
  }
]
```

## 6. Обогащение данных (Социальные сети, Время начала и Панели)

Данные о соцсетях, времени начала стрима и панелях под стримом недоступны в основном запросе каталога. Их необходимо собирать отдельными запросами. Это может занять время, поэтому реализована продвинутая система батчинга и управления.

### 6.1 Батч-запросы
- **Соц. сети и Время начала**: Извлекаются единым GraphQL-запросом. Расширение собирает логины стримеров пачками (батчами) по **30 штук** и делает один массивный POST запрос.
- **Панели**: Извлекаются запросом `ChannelPanels` по `userId`. Панели тяжеловесны, поэтому они собираются батчами по **20 штук**. Панели проходят очистку от пустых элементов; извлекаются только `title`, `linkURL`, `description` и `altText`.

### 6.2 Управление процессом (Пауза, Возобновление, Отмена)
- Функция `enrichData()` разбита на управляемые шаги. 
- Пользователь может нажать кнопку **«Стоп»**. Процесс не сбрасывается: `background.js` сохраняет текущий прогресс (`enrichDone`, `enrichTotal`) и промежуточный массив данных в `chrome.storage.local`, переводя статус в `enrich_paused`.
- Кнопка **«Продолжить»** снова вызывает `enrichData()`, которая читает массив из хранилища и продолжает сбор только для тех каналов, где массивы `social` / `panels` равны `undefined`.
- Кнопка **«Отменить»** принудительно заменяет оставшиеся `undefined` на `null`. Это помечает процесс обогащения как завершенный, и отсутствующие поля просто не попадут в финальный экспорт.

## 7. Машина состояний интерфейса (UI State Machine)

### 7.1 Сохранение состояния интерфейса (UI Persistence)
Весь пользовательский интерфейс реактивен и обладает персистентностью. При любом изменении состояния чекбоксов, выборе языков или переключении форматов вызывается функция `saveUISettings()`, которая сохраняет текущую конфигурацию в `chrome.storage.local`. При повторном открытии расширения функция `loadUISettings()` моментально восстанавливает все параметры.

### 7.2 Управление фазами сбора (Phases)
Вся логика в `popup.js` построена вокруг реактивной машины состояний. Сервис-воркер отправляет сообщения `state_update` с объектом состояния:

```javascript
{ 
  phase: 'idle' | 'running' | 'enriching' | 'enrich_paused' | 'done' | 'error', 
  collected: 450, 
  target: 0, 
  enrichStep: 'social', 
  enrichDone: 150, 
  enrichTotal: 450,
  error: null 
}
```

В зависимости от фазы (`phase`), интерфейс `popup.js` (функция `applyState`):
- Переключает видимость прогресс-бара и кнопок (Собрать, Стоп, Завершить, Продолжить, Отменить, Скачать файл).
- Меняет стиль статус-пилюли (голубая/желтая/красная/зеленая).
- Анимирует шкалу загрузки.

## 8. Генерация и Экспорт файлов

Скачивание не происходит автоматически после сбора (поскольку пользователь может захотеть выбрать другой формат). За скачивание отвечает кнопка "Скачать файл".

### 8.1 Обход лимитов памяти MV3 (Message Passing)
В Manifest V3 передача огромных массивов данных (тысячи стримов с длинными строками `description`) через встроенную систему `chrome.runtime.sendMessage` может привести к крэшу Service Worker'а из-за лимитов на размер сообщений. Поэтому `background.js` не генерирует `Blob`-файл внутри себя. 
Вместо этого он через API `chrome.scripting.executeScript` пробрасывает сырой массив как аргумент в функцию `triggerDownload`, которая исполняется в контексте открытой вкладки Twitch. Браузер без проблем выделяет память для страницы, где функция локально генерирует `Blob` и инициирует скачивание через невидимый тег `<a>`.

### 8.2 Формат JSON
Массив данных пропускается через фильтр. Если пользователь не ставил галочку `Соц. сети`, либо если они не были собраны (остались `null` после отмены), ключи `social` и `panels` не включаются в объекты JSON.
Поле времени начала трансляции и продолжительности опционально разделены на `startTime` и `duration` и форматируются согласно настройкам интерфейса (ISO 8601, Unixtime, местное время и т.д.).

### 8.3 Формат Markdown
Скрипт генерирует красивый, легкочитаемый Markdown.
- **Описания и панели** оборачиваются в HTML-теги `<details><summary>Развернуть...</summary><blockquote>...</blockquote></details>`. Это позволяет тексту не "ломать" разметку списка и делает чтение файла удобным.
- **Соцсети** выводятся в виде гиперссылок: `[Название](URL)`.
- **Панели** могут содержать сложную разметку, поэтому расширение корректно обрабатывает комбинации `title` + `linkURL` и сохраняет переносы строк в `description`.

Затем создается `Blob`, формируется временный `ObjectURL`, программно нажимается тег `<a>` и файл сохраняется на диск пользователя.

## 9. Дебаг-логирование и Управление кэшем

### 9.1 Кольцевой буфер логов
Для расследования багов `background.js` содержит функцию `addLog()`. 
Она добавляет запись с таймстампом в массив `_logsBuffer`. Буфер ограничен 500 записями (старые удаляются). Буфер хранится в `chrome.storage.local`.
Логируется абсолютно все: HTTP статусы ответов, пойманные заголовки, курсоры, параметры GQL. 

В интерфейсе (открывается кнопкой с иконкой "Жука" в шапке) пользователь может нажать **«Скачать дебаг-логи»**, что выгрузит этот буфер в текстовый файл `twitch_scraper_debug_<timestamp>.txt`. Также можно отключить логирование для экономии памяти браузера.

### 9.2 Полный экстренный сброс
Кнопка **«Полный сброс расширения (Экстренный)»** отправляет сигнал `full_reset`.
`background.js`:
1. Принудительно обрывает все активные циклы `while` и `for`.
2. Очищает все переменные состояния (`_isRunning`, `_shouldStopEnrich` и т.д.).
3. Возвращает объект `twitchHeaders` к дефолтным невалидным значениям.
4. Вызывает `chrome.storage.local.clear()`, удаляя весь кэш, логи и сохраненные настройки.
5. Интерфейс перезагружается в "чистое" состояние `idle`. Это гарантирует, что любой "залипший" баг или поврежденный кэш расширения будет полностью устранен одним кликом.
