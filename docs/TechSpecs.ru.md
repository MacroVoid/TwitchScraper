# Twitch Scraper — Техническая документация

## 1. Обзор

**Twitch Scraper** — это расширение для браузера (Google Chrome, Manifest V3), предназначенное для извлечения данных о прямых трансляциях из любой категории на Twitch (например, `twitch.tv/directory/category/minecraft`).

Расширение обходит механизмы защиты Twitch (CORS, токены Integrity) путем пассивного перехвата сетевых заголовков из легитимной пользовательской сессии. Затем оно автономно выполняет серию запросов к недокументированному GraphQL (GQL) API Twitch. Собранные данные — основная информация о трансляции, ссылки на социальные сети и панели канала — агрегируются и экспортируются в формате `JSON` или `Markdown`.

---

## 2. Архитектура и структура файлов

Вся ресурсоемкая обработка перенесена в изолированный фоновый процесс, что позволяет не влиять на работу страницы Twitch и обходить ограничения кросс-доменных (cross-origin) запросов.

| Файл | Описание |
| --- | --- |
| `manifest.json` | Manifest V3. Объявляет разрешения: `webRequest` (пассивный перехват заголовков), `storage` (сохранение состояния и данных), `scripting` (внедрение скрипта загрузки) и разрешения для хостов `*.twitch.tv` и `gql.twitch.tv`. |
| `background.js` | Основной движок (Service Worker). Обрабатывает всю бизнес-логику: перехват заголовков, запросы к GQL, обход особенностей пагинации Twitch, пакетная обработка запросов социальных сетей и панелей, управление конечным автоматом состояний (пауза/отмена) и сохранение промежуточных результатов в `chrome.storage.local`. |
| `popup.html` | Макет пользовательского интерфейса (UI). Включает настройки фильтров, выбор языка, лимиты, параметры формата экспорта, индикатор прогресса и панель журнала отладки (debug log). |
| `popup.js` | Логика UI. Отправляет сообщения в `background.js` (`start_collection`, `stop_collection`, `resume_enrich`, `download_last_data` и т.д.) и реактивно обновляет интерфейс (индикаторы выполнения, статусы) при получении сообщений `state_update` от Service Worker. |
| `content.js` | Минимальный Content Script. Ранее использовался для выполнения запросов; в версии 2.0 служит исключительно безопасной точкой внедрения — `background.js` использует API `scripting` для выполнения `triggerDownload` в контексте страницы Twitch с целью генерации объекта `Blob` и запуска загрузки файла. |

## 3. Перехват заголовков и обход защиты Twitch

### 3.1 Зачем нужен перехват

GQL API Twitch (`gql.twitch.tv/gql`) защищен от автоматизированных скриптов системой проверки целостности (**Integrity Check**). Каждый запрос требует наличия заголовка `Client-Integrity` — токена, криптографически подписанного обфусцированным скриптом Twitch с использованием цифрового отпечатка браузера (fingerprint) пользователя. Расширение не может сгенерировать его самостоятельно.

### 3.2 Пассивный перехват (`webRequest`)

`background.js` использует слушатель `chrome.webRequest.onSendHeaders`. Когда веб-сайт Twitch (открытый во вкладке) выполняет легитимный GQL-запрос в рамках нормального рендеринга страницы, расширение перехватывает следующие исходящие заголовки в процессе их передачи:

* `Client-Id`
* `Client-Integrity`
* `Authorization`
* `X-Device-Id`
* `Client-Version`
* `Client-Session-Id`

### 3.3 Хранение и нормализация

Перехваченные заголовки сохраняются в `chrome.storage.local`. Поскольку объекты JavaScript чувствительны к регистру, в ранних версиях возникали ошибки `400 Bad Request`, вызванные дублированием вариантов заголовков (например, `Client-ID` и `Client-Id`).

В версии 2.0 применяется строгая карта нормализации (`HEADER_KEY_MAP`). Заголовки всегда преобразуются в стандартный формат Pascal-Kebab-Case и дедублируются. Функция `ensureHeadersLoaded()` гарантирует, что расширение всегда использует самые актуальные валидные токены. Если срок действия токена истекает, расширение выводит ошибку с предложением пользователю нажать `F5` на вкладке Twitch для захвата нового набора данных.

## 4. Сбор данных о трансляциях: GQL API и известные особенности

Сбор данных инициируется сообщением `start_collection`. `background.js` извлекает идентификатор (`slug`) категории из URL-адреса активной вкладки и запускает цикл запросов `DirectoryPageGame`.

### 4.1 Поиск по идентификатору (slug)

В запросах используется аргумент `game(slug: $slug)`, а не `game(name: $slug)`. Поиск по названию не работает для игр со сложными заголовками или специальными символами; `slug` всегда корректно определяет директорию.

### 4.2 Поведение языкового фильтра

Когда пользователь выбирает «Все языки» (All Languages), расширение отправляет `broadcasterLanguages: []` (пустой массив), что дает указание Twitch возвращать трансляции на всех языках. При выборе конкретных языков (например, `RU`, `EN`), массив заполняется их соответствующими кодами.

### 4.3 Ошибка пагинации Twitch (`VIEWER_COUNT_ASC`) и порядок сортировки

У Twitch есть известная проблема с базой данных:

* При сортировке по возрастанию (`VIEWER_COUNT_ASC`) база данных формирует нестабильные курсоры, что приводит к зацикливанию ответа и возврату дубликатов трансляций с малым числом зрителей.
* При достижении трансляций с 0 зрителей Twitch кодирует в курсор Unix-метку времени начала трансляции (например, `s = 1781455831`). Следующий запрос страницы затем ищет трансляции, где `viewersCount > 1.78 миллиарда`, и возвращает пустой набор результатов, резко завершая сбор данных.

**Решение в версии 2.0:** Когда пользователь запускает сбор данных без ограничения количества трансляций (по всей категории), расширение переопределяет настройку UI для серверных запросов и всегда выполняет выборку с параметром `VIEWER_COUNT` (по убыванию). Это обеспечивает стабильную и непрерывную серверную пагинацию. Выбранный пользователем порядок сортировки затем применяется **в оперативной памяти** (in-memory) непосредственно перед экспортом.

### 4.4 Обнаружение зацикливания и ограничение частоты запросов (Rate Limiting)

Цикл сбора данных включает задержку в 150 мс между страницами. Если Twitch зависает и возвращает один и тот же `cursor` и `id` последней трансляции на протяжении нескольких последовательных страниц, расширение обнаруживает бесконечный цикл и прерывает работу.

### 4.5 Трансляции «Только для подписчиков» (Sub-only)

Интерфейс включает опцию «Включить трансляции только для подписчиков» (Include Sub-Only). При включении к параметрам запроса GraphQL добавляется `includeRestricted: [SUB_ONLY_LIVE]`, что заставляет Twitch возвращать трансляции, которые в противном случае видны только платным подписчикам канала.

## 5. Структуры запросов и ответов (Справочник по GQL)

Расширение взаимодействует с `https://gql.twitch.tv/gql` через метод `POST`. Тело запроса всегда представлено в формате JSON и содержит поля `query` (или `operationName` для сохраненных запросов) и `variables`.

### 5.1 Список трансляций директории (`DirectoryPageGame`)

Используется для получения списка прямых трансляций.

**Запрос:**

```json
{
  "query": "query DirectoryPageGame($slug: String!, $cursor: Cursor) { game(slug: $slug) { streams(first: 100, after: $cursor, options: { sort: VIEWER_COUNT, broadcasterLanguages: [\"EN\"], recommendationsContext: { platform: \"web\" }, systemFilters: [] }) { pageInfo { hasNextPage } edges { cursor node { id title viewersCount broadcaster { id login displayName description followers { totalCount } } freeformTags { name } game { name displayName } } } } } }",
  "variables": {
    "slug": "minecraft",
    "cursor": null
  }
}

```

**Ответ:** Вложенный JSON. Данные о трансляции находятся в `data.game.streams.edges`. Каждое ребро (edge) содержит `cursor` (для запроса следующей страницы) и `node` (сведения о трансляции).

```json
{
  "data": {
    "game": {
      "streams": {
        "pageInfo": { "hasNextPage": true },
        "edges": [
          {
            "cursor": "eyJzIjowLjM0Njg1OTYxMDAyMTc4MDIsImQiOmZhbHNlLCJ0Ijp0cnVlfQ==",
            "node": {
              "id": "51234567890",
              "title": "Morning Stream",
              "viewersCount": 15400,
              "broadcaster": {
                "id": "12345678",
                "login": "streamer_login",
                "displayName": "StreamerName",
                "description": "Channel description...",
                "followers": { "totalCount": 250000 }
              },
              "freeformTags": [ { "name": "English" }, { "name": "Survival" } ],
              "game": { "name": "Minecraft", "displayName": "Minecraft" }
            }
          }
        ]
      }
    }
  }
}

```

### 5.2 Дополнительные данные канала (`GetChannelExtras`)

Ссылки на социальные сети и время начала трансляции (uptime) недоступны в основном запросе директории, поэтому расширение использует пакетную обработку (batching) GraphQL для их отдельного запроса.

**Запрос (пакетный):**

```json
[
  {
    "query": "query GetChannelExtras($login: String!) { user(login: $login) { login stream { createdAt } channel { socialMedias { name title url } } } }",
    "variables": { "login": "streamer_login_1" }
  },
  {
    "query": "query GetChannelExtras($login: String!) { user(login: $login) { login stream { createdAt } channel { socialMedias { name title url } } } }",
    "variables": { "login": "streamer_login_2" }
  }
]

```

**Ответ:** Массив ответов, содержащих временную метку начала трансляции (`createdAt`) и ссылки на социальные сети.

```json
[
  {
    "data": {
      "user": {
        "login": "streamer_login_1",
        "stream": {
          "createdAt": "2026-06-15T08:15:30Z"
        },
        "channel": {
          "socialMedias": [
            { "name": "youtube", "title": "YouTube", "url": "https://youtube.com/..." },
            { "name": "twitter", "title": "Twitter", "url": "https://x.com/..." }
          ]
        }
      }
    }
  }
]

```

### 5.3 Панели канала (`ChannelPanels`)

Использует `operationName` Twitch с хешем `persistedQuery` вместо полного встроенного (inline) запроса. Запросы группируются по `id` канала (числовой идентификатор, а не логин).

**Запрос:**

```json
[
  {
    "operationName": "ChannelPanels",
    "variables": { "id": "12345678" },
    "extensions": {
      "persistedQuery": {
        "version": 1,
        "sha256Hash": "06d5b518ba3b016ebe62000151c9a81f162f2a1430eb1cf9ad0678ba56d0a768"
      }
    }
  }
]

```

**Ответ:** Данные находятся в `data.user.panels`.

```json
[
  {
    "data": {
      "user": {
        "id": "12345678",
        "panels": [
          {
            "__typename": "DefaultPanel",
            "title": "Rules",
            "linkURL": "https://discord.gg/...",
            "description": "Don't spam in chat.",
            "altText": "Rules banner"
          }
        ]
      }
    }
  }
]

```

## 6. Расширенный сбор данных (Социальные сети, Панели, Время работы трансляции)

Ссылки на социальные сети, панели каналов и время работы трансляции (uptime) либо недоступны, либо представлены не полностью в первичном запросе директории, и их необходимо получать отдельно. Расширение использует пакетную обработку и систему сохранения состояний для эффективного управления этим процессом.

### 6.1 Размеры пакетов и обработка данных

* **Социальные сети и время работы (Uptime):** Запрашиваются совместно через `GetChannelExtras` пакетами по **30** логинов за один POST-запрос. Каждый ответ включает как ссылки на социальные сети, так и временную метку начала трансляции (`createdAt`), которая используется для расчета продолжительности.
* **Панели:** Запрашиваются через `ChannelPanels` пакетами по **20** каналов, используя их идентификатор пользователя (`userId`). Данные панелей фильтруются для сохранения только полей `title`, `linkURL`, `description` и `altText`; пустые записи отбрасываются.

### 6.2 Пауза, возобновление и отмена

* Функция `enrichData()` разделена на дискретные этапы, которые проверяют наличие сигналов прерывания.
* Когда пользователь нажимает **Стоп (Stop)**, текущий прогресс (`enrichDone`, `enrichTotal`) и массив промежуточных данных сохраняются в `chrome.storage.local`, а статус переходит в `enrich_paused`.
* Нажатие **Продолжить (Continue)** повторно вызывает `enrichData()`, которая считывает данные из хранилища и возобновляет работу только для тех каналов, где `social` или `panels` все еще имеют значение `undefined`.
* Нажатие **Отменить (Cancel)** заменяет все оставшиеся значения `undefined` на `null`, отмечая расширенный сбор данных как завершенный. Поля, оставленные как `null`, исключаются из конечного экспорта.

## 7. Конечный автомат состояний пользовательского интерфейса (UI)

### 7.1 Сохранение настроек

Пользовательский интерфейс является полностью реактивным и сохраняемым. Любое изменение флажков, выбора языка или параметров формата запускает `saveUISettings()`, которая записывает текущую конфигурацию в `chrome.storage.local`. При следующем открытии `loadUISettings()` немедленно восстанавливает все настройки.

### 7.2 Управление фазами

Скрипт `popup.js` управляется реактивным автоматом состояний. Service Worker рассылает сообщения `state_update`, содержащие объект состояния:

```javascript
{
  phase: 'idle' | 'running' | 'enriching' | 'enrich_paused' | 'done' | 'error',
  collected: 450,
  target: 0,
  enrichStep: 'social',
  enrichDone: 150,
  enrichTotal: 450,
  error: null
}

```

Функция `applyState` в `popup.js` реагирует на каждую фазу (`phase`) следующим образом:

* Отображает или скрывает соответствующие кнопки действий (Collect, Stop, Finish, Continue, Cancel, Download).
* Обновляет стиль визуального индикатора статуса (синий / желтый / красный / зеленый).
* Анимирует индикатор выполнения (progress bar).

### 7.3 Система локализации

Интерфейс поддерживает динамическое переключение языка (русский и английский):

* Выбранный язык сохраняется в `localStorage` под ключом `appLang` и восстанавливается при запуске.
* Функция `applyTranslations()` обходит DOM-дерево и устанавливает локализованные строки для всех элементов с атрибутами `data-i18n` (текстовое содержимое) и `data-i18n-title` (всплывающие подсказки).
* Сообщения о статусе Service Worker во время фаз сбора данных, расширенного сбора и паузы форматируются реактивно с использованием соответствующих языковых шаблонов из `i18n.js`.

## 8. Генерация файлов и экспорт

Экспорт не запускается автоматически после сбора данных, поскольку пользователь может захотеть изменить формат перед загрузкой. Кнопка **Скачать (Download)** инициирует экспорт.

### 8.1 Обход лимитов памяти Manifest V3

В Manifest V3 передача больших массивов данных (тысячи трансляций с длинными строками `description`) через `chrome.runtime.sendMessage` может привести к сбою (crash) Service Worker из-за ограничений на размер сообщений. Во избежание этого `background.js` не генерирует `Blob` внутри себя.

Вместо этого, через `chrome.scripting.executeScript`, он передает массив необработанных данных в качестве аргумента функции `triggerDownload`, которая выполняется в контексте открытой вкладки Twitch. Браузер выделяет память в контексте страницы, где функция создает `Blob` и инициирует загрузку через программное нажатие на элемент `<a>`.

### 8.2 Экспорт в JSON

Перед экспортом массив данных фильтруется в соответствии с настройками пользователя. Если сбор данных социальных сетей (`Social`) или панелей (`Panels`) был отключен или отменен (значения остаются `null`), соответствующие ключи исключаются из каждого JSON-объекта. Настройки формата времени (ISO 8601, Unix-метка, GMT, локальное время, HH:MM:SS и т.д.) применяются к полям `startTime` и `duration` на этом этапе.

### 8.3 Экспорт в Markdown

Вывод в формате Markdown структурирован для удобства чтения:

* Длинный контент (описания, панели) оборачивается в теги `<details><summary>Expand...</summary><blockquote>...</blockquote></details>` для предотвращения нарушения верстки.
* Ссылки на социальные сети отображаются в виде `[Имя](URL)`.
* Записи панелей обрабатывают комбинации `title` + `linkURL` и сохраняют разрывы строк внутри `description`.
* **Адаптация языка**: Все заголовки разделов, метки свойств трансляции (Канал, Зрители, Время начала, Продолжительность и т.д.) и заголовки сводок (details summary) локализуются в соответствии с активным на момент экспорта языком пользовательского интерфейса (значение `lang` отправляется в Service Worker в сообщении `download_last_data`).

После сборки контента создается объект `Blob`, генерируется временный `ObjectURL`, и загрузка инициируется программным нажатием на элемент `<a>`.

## 9. Журналирование отладки и сброс

### 9.1 Буфер журнала (Log buffer)

Скрипт `background.js` включает функцию `addLog()` для диагностики. Записи журнала (с временными метками) добавляются в массив `_logsBuffer`, который ограничен 500 записями — старые записи удаляются по мере поступления новых. Буфер сохраняется в `chrome.storage.local`.

Регистрируемые события включают: HTTP-статусы ответов, перехваченные заголовки, курсоры пагинации и параметры GQL.

Панель отладки (доступная по иконке жука в заголовке) предоставляет кнопку **Скачать логи отладки (Download debug logs)**, которая экспортирует буфер в файл `twitch_scraper_debug_<timestamp>.txt`. Ведение журнала можно отключить для снижения потребления памяти браузером.

### 9.2 Экстренный сброс (Emergency reset)

Кнопка **Экстренный сброс (Emergency Reset)** отправляет сигнал `full_reset` в `background.js`, который:

1. Прерывает все активные циклы `while` и `for`.
2. Очищает все переменные состояния времени выполнения (`_isRunning`, `_shouldStopEnrich` и т.д.).
3. Сбрасывает `twitchHeaders` до невалидных значений по умолчанию.
4. Вызывает `chrome.storage.local.clear()`, удаляя все кэшированные данные, журналы и сохраненные настройки.
5. Возвращает интерфейс в чистое исходное состояние (`idle`).

Это обеспечивает надежное однократное восстановление (recovery) из любого зависшего состояния или при повреждении кэша.
