# Twitch Scraper — Техническая документация

## 1. Общее описание

**Twitch Scraper** — браузерное расширение (Google Chrome, Manifest V3) для сбора данных о прямых трансляциях из любой категории на Twitch (например, `twitch.tv/directory/category/minecraft`).

Расширение обходит защитные механизмы Twitch (CORS, Integrity-токены) путём пассивного перехвата сетевых заголовков из легитимной пользовательской сессии, после чего самостоятельно выполняет серию запросов к недокументированному GraphQL (GQL) API Twitch. Собранные данные — базовая информация о стримах, ссылки на социальные сети и панели каналов — агрегируются и экспортируются в формате `JSON` или `Markdown`.

---

## 2. Архитектура и структура файлов

Вся ресурсоёмкая обработка вынесена в изолированный фоновый процесс, что не влияет на производительность страницы Twitch и позволяет обойти ограничения на запросы между источниками (CORS).

| Файл | Описание |
|------|----------|
| `manifest.json` | Manifest V3. Объявляет разрешения: `webRequest` (пассивный перехват заголовков), `storage` (сохранение состояния и данных), `scripting` (внедрение скрипта загрузки), а также разрешения хоста для `*.twitch.tv` и `gql.twitch.tv`. |
| `background.js` | Основной движок (Service Worker). Реализует всю бизнес-логику: перехват заголовков, выполнение GQL-запросов, обработку особенностей пагинации Twitch, пакетные запросы социальных сетей и панелей, управление машиной состояний (пауза/отмена), сохранение промежуточных результатов в `chrome.storage.local`. |
| `popup.html` | Разметка интерфейса. Включает настройки фильтров, выбор языков, лимиты, параметры формата экспорта, отображение прогресса и панель отладочных журналов. |
| `popup.js` | Логика интерфейса. Отправляет сообщения в `background.js` (`start_collection`, `stop_collection`, `resume_enrich`, `download_last_data` и др.) и реактивно обновляет UI (прогресс-бары, индикаторы состояния) при получении сообщений `state_update` от Service Worker. |
| `content.js` | Минимальный Content Script. Ранее использовался для выполнения запросов; в v2.0 служит исключительно точкой безопасного внедрения — `background.js` через API `scripting` запускает функцию `triggerDownload` в контексте страницы Twitch для формирования `Blob` и инициации скачивания файла. |

## 3. Перехват заголовков и обход защиты Twitch

### 3.1 Необходимость перехвата

GQL API Twitch (`gql.twitch.tv/gql`) защищён от автоматизированных скриптов системой **Integrity Check**. Каждый запрос требует заголовка `Client-Integrity` — токена, криптографически подписанного обфусцированным скриптом Twitch с использованием цифрового отпечатка браузера пользователя. Расширение не может сгенерировать этот токен самостоятельно.

### 3.2 Пассивный перехват (`webRequest`)

`background.js` использует обработчик `chrome.webRequest.onSendHeaders`. Когда Twitch (открытый в вкладке браузера) выполняет легитимный GQL-запрос в процессе штатного рендеринга страницы, расширение перехватывает следующие исходящие заголовки:

- `Client-Id`
- `Client-Integrity`
- `Authorization`
- `X-Device-Id`
- `Client-Version`
- `Client-Session-Id`

### 3.3 Хранение и нормализация

Перехваченные заголовки сохраняются в `chrome.storage.local`. Поскольку объекты JavaScript чувствительны к регистру, в ранних версиях дублирующиеся варианты написания (например, `Client-ID` и `Client-Id`) приводили к ошибкам `400 Bad Request`.

В v2.0 применяется строгая карта нормализации (`HEADER_KEY_MAP`): заголовки всегда приводятся к стандартному формату Pascal-Kebab-Case, дубликаты удаляются. Функция `ensureHeadersLoaded()` гарантирует использование актуальных токенов. При истечении срока действия токена расширение выводит сообщение об ошибке с предложением нажать `F5` на вкладке Twitch для получения нового набора заголовков.

## 4. Сбор стримов: GQL API и известные особенности

Сбор инициируется сообщением `start_collection`. `background.js` извлекает `slug` категории из URL активной вкладки и запускает цикл запросов `DirectoryPageGame`.

### 4.1 Поиск по slug

В запросах используется аргумент `game(slug: $slug)`, а не `game(name: $slug)`. Поиск по названию некорректно работает для игр со сложными наименованиями и специальными символами; `slug` всегда однозначно идентифицирует директорию.

### 4.2 Поведение языкового фильтра

При выборе «Все языки» расширение передаёт `broadcasterLanguages: []` (пустой массив), что возвращает стримы на всех языках. При выборе конкретных языков (например, `RU`, `EN`) массив заполняется соответствующими кодами.

### 4.3 Баг пагинации Twitch (`VIEWER_COUNT_ASC`) и сортировка

В Twitch существует известная проблема на уровне базы данных:

- При сортировке по возрастанию (`VIEWER_COUNT_ASC`) БД генерирует нестабильные курсоры, из-за чего ответы зацикливаются и возвращают дублирующиеся стримы с малым числом зрителей.
- При достижении стримов с 0 зрителями Twitch кодирует Unix-временну́ю метку начала стрима как курсор (например, `s = 1781455831`). Следующий запрос ищет стримы с `viewersCount > 1,78 млрд` и возвращает пустой результат, прерывая сбор.

**Решение в v2.0:** при запуске без лимита (сбор всей категории) расширение игнорирует настройку интерфейса и всегда запрашивает данные с параметром `VIEWER_COUNT` (по убыванию). Это обеспечивает стабильную серверную пагинацию без пропусков. Выбранный пользователем порядок сортировки применяется **в памяти** непосредственно перед экспортом.

### 4.4 Защита от зацикливания и ограничение частоты запросов

Между страницами установлена задержка 150 мс. Если Twitch зависает и возвращает одинаковые `cursor` и `id` последнего стрима на нескольких страницах подряд, расширение фиксирует бесконечный цикл и прерывает сбор.

### 4.5 Стримы только для подписчиков

Интерфейс предоставляет опцию «Включить Sub-Only». При её активации к параметрам GraphQL-запроса добавляется флаг `includeRestricted: [SUB_ONLY_LIVE]`, вследствие чего Twitch возвращает стримы, доступные для просмотра исключительно платным подписчикам канала.

## 5. Структуры запросов и ответов (GQL)

Расширение взаимодействует с `https://gql.twitch.tv/gql` через метод `POST`. Тело запроса всегда передаётся в формате JSON и содержит поля `query` (или `operationName` для persisted queries) и `variables`.

### 5.1 Список стримов директории (`DirectoryPageGame`)

Используется для получения списка активных трансляций.

**Запрос:**
```json
{
  "query": "query DirectoryPageGame($slug: String!, $cursor: Cursor) { game(slug: $slug) { streams(first: 100, after: $cursor, options: { sort: VIEWER_COUNT, broadcasterLanguages: [\"EN\"], recommendationsContext: { platform: \"web\" }, systemFilters: [] }) { pageInfo { hasNextPage } edges { cursor node { id title viewersCount broadcaster { id login displayName description followers { totalCount } } freeformTags { name } game { name displayName } } } } } }",
  "variables": {
    "slug": "minecraft",
    "cursor": null
  }
}
```

**Ответ:** Вложенный JSON. Данные стримов находятся в `data.game.streams.edges`. Каждый элемент содержит `cursor` (для следующего запроса) и `node` (сведения о стриме).

```json
{
  "data": {
    "game": {
      "streams": {
        "pageInfo": { "hasNextPage": true },
        "edges": [
          {
            "cursor": "eyJzIjowLjM0Njg1OTYxMDAyMTc4MDIsImQiOmZhbHNlLCJ0Ijp0cnVlfQ==",
            "node": {
              "id": "51234567890",
              "title": "Morning Stream",
              "viewersCount": 15400,
              "broadcaster": {
                "id": "12345678",
                "login": "streamer_login",
                "displayName": "StreamerName",
                "description": "Channel description...",
                "followers": { "totalCount": 250000 }
              },
              "freeformTags": [ { "name": "English" }, { "name": "Survival" } ],
              "game": { "name": "Minecraft", "displayName": "Minecraft" }
            }
          }
        ]
      }
    }
  }
}
```

### 5.2 Социальные сети (`GetChannelSocial`)

Данные социальных сетей недоступны в запросе директории, поэтому расширение использует GraphQL batching — массив объектов запросов в одном POST.

**Запрос (пакетный):**
```json
[
  {
    "query": "query GetChannelSocial($login: String!) { user(login: $login) { login channel { socialMedias { name title url } } } }",
    "variables": { "login": "streamer_login_1" }
  },
  {
    "query": "query GetChannelSocial($login: String!) { user(login: $login) { login channel { socialMedias { name title url } } } }",
    "variables": { "login": "streamer_login_2" }
  }
]
```

**Ответ:** Массив ответов. Данные социальных сетей находятся в `data.user.channel.socialMedias`.

```json
[
  {
    "data": {
      "user": {
        "login": "streamer_login_1",
        "channel": {
          "socialMedias": [
            { "name": "youtube", "title": "YouTube", "url": "https://youtube.com/..." },
            { "name": "twitter", "title": "Twitter", "url": "https://x.com/..." }
          ]
        }
      }
    }
  }
]
```

### 5.3 Панели канала (`ChannelPanels`)

Использует `operationName` и хэш `persistedQuery` вместо полного текста запроса. Запросы группируются по числовому `id` канала (не по логину).

**Запрос:**
```json
[
  {
    "operationName": "ChannelPanels",
    "variables": { "id": "12345678" },
    "extensions": {
      "persistedQuery": {
        "version": 1,
        "sha256Hash": "06d5b518ba3b016ebe62000151c9a81f162f2a1430eb1cf9ad0678ba56d0a768"
      }
    }
  }
]
```

**Ответ:** Данные находятся в `data.user.panels`.

```json
[
  {
    "data": {
      "user": {
        "id": "12345678",
        "panels": [
          {
            "__typename": "DefaultPanel",
            "title": "Rules",
            "linkURL": "https://discord.gg/...",
            "description": "Don't spam in chat.",
            "altText": "Rules banner"
          }
        ]
      }
    }
  }
]
```

## 6. Расширенный сбор данных (социальные сети, панели, время работы)

Ссылки на социальные сети, панели каналов и точное время работы стрима отсутствуют или неполны в основном запросе директории и должны запрашиваться отдельно. Для эффективного управления этим процессом расширение использует пакетные запросы и систему сохранения состояния.

### 6.1 Размеры пакетов и обработка данных

- **Социальные сети:** запрашиваются через `GetChannelSocial` пакетами по **30** логинов на один POST-запрос.
- **Панели:** запрашиваются через `ChannelPanels` пакетами по **20** по `userId` канала. Из данных панелей сохраняются только поля `title`, `linkURL`, `description` и `altText`; пустые записи отбрасываются.
- **Время работы:** метаданные стрима (`createdAt`) запрашиваются через дополнительные GQL-запросы, что обеспечивает точное время начала и корректный расчёт продолжительности.

### 6.2 Пауза, возобновление и отмена

- Функция `enrichData()` разбита на отдельные шаги с проверкой сигналов прерывания.
- При нажатии **Стоп** текущий прогресс (`enrichDone`, `enrichTotal`) и промежуточный массив данных сохраняются в `chrome.storage.local`, статус переходит в `enrich_paused`.
- **Продолжить** повторно вызывает `enrichData()`, которая читает данные из хранилища и возобновляет сбор только для каналов, где `social` или `panels` ещё имеют значение `undefined`.
- **Отмена** заменяет все оставшиеся значения `undefined` на `null`, завершая процесс обогащения. Поля со значением `null` не включаются в итоговый экспорт.

## 7. Машина состояний интерфейса

### 7.1 Сохранение настроек

Интерфейс полностью реактивен и сохраняет состояние между сессиями. Любое изменение чекбоксов, языков или параметров формата вызывает `saveUISettings()`, которая записывает текущую конфигурацию в `chrome.storage.local`. При следующем открытии расширения `loadUISettings()` мгновенно восстанавливает все настройки.

### 7.2 Управление фазами

`popup.js` управляется реактивной машиной состояний. Service Worker транслирует сообщения `state_update`, содержащие объект состояния:

```javascript
{
  phase: 'idle' | 'running' | 'enriching' | 'enrich_paused' | 'done' | 'error',
  collected: 450,
  target: 0,
  enrichStep: 'social',
  enrichDone: 150,
  enrichTotal: 450,
  error: null
}
```

Функция `applyState` в `popup.js` реагирует на каждую фазу:

- Отображает или скрывает соответствующие кнопки действий (Собрать, Стоп, Завершить, Продолжить, Отмена, Скачать)
- Обновляет стиль индикатора состояния (синий / жёлтый / красный / зелёный)
- Анимирует прогресс-бар

### 7.3 Локализация интерфейса

Интерфейс поддерживает динамическое переключение языков (русский и английский):
- Выбранный язык сохраняется в `localStorage` под ключом `appLang` и восстанавливается при запуске.
- Функция `applyTranslations()` обходит DOM и подставляет локализованные строки для всех элементов с атрибутами `data-i18n` (текстовое содержимое) и `data-i18n-title` (всплывающие подсказки).
- Информационные сообщения Service Worker на стадиях сбора данных, обогащения и приостановки форматируются реактивно с использованием соответствующих языковых шаблонов из `i18n.js`.

## 8. Формирование и экспорт файлов

Экспорт не запускается автоматически по завершении сбора, поскольку пользователь может изменить формат перед скачиванием. Экспорт инициируется кнопкой **Скачать**.

### 8.1 Обход ограничений памяти MV3

В Manifest V3 передача больших массивов данных (тысячи стримов с длинными строками `description`) через `chrome.runtime.sendMessage` может привести к аварийному завершению Service Worker из-за ограничений на размер сообщений. Во избежание этого `background.js` не формирует `Blob` самостоятельно.

Вместо этого через `chrome.scripting.executeScript` исходный массив данных передаётся аргументом в функцию `triggerDownload`, выполняющуюся в контексте открытой вкладки Twitch. Браузер выделяет память в контексте страницы, где функция создаёт `Blob` и инициирует скачивание через программный клик по элементу `<a>`.

### 8.2 Экспорт в JSON

Перед экспортом массив данных фильтруется в соответствии с настройками пользователя. Если сбор социальных сетей или панелей был отключён или отменён (значения остались `null`), соответствующие ключи исключаются из JSON-объектов. На этом этапе к полям `startTime` и `duration` применяются настройки формата времени (ISO 8601, Unix Timestamp, GMT, локальное время, HH:MM:SS и др.).

### 8.3 Экспорт в Markdown

Markdown-вывод структурирован для удобства чтения:

- Длинный контент (`description`, панели) оборачивается в `<details><summary>Развернуть...</summary><blockquote>...</blockquote></details>` во избежание нарушения структуры списка.
- Ссылки на социальные сети выводятся в формате `[Название](URL)`.
- Записи панелей обрабатывают комбинации `title` + `linkURL` и сохраняют переносы строк внутри `description`.
- **Языковая адаптация**: все заголовки разделов, метки свойств стрима (Канал, Зрители, Время начала, Продолжительность и др.), а также подписи сворачиваемых блоков локализуются на базе текущего выбранного языка интерфейса в момент инициации экспорта (значение `lang` передаётся Service Worker в сообщении `download_last_data`).

После формирования контента создаётся `Blob`, генерируется временный `ObjectURL`, и скачивание запускается программным кликом по элементу `<a>`.

## 9. Отладочные журналы и сброс

### 9.1 Буфер журналов

`background.js` содержит функцию `addLog()` для диагностики. Записи журнала (с временными метками) добавляются в массив `_logsBuffer`, ёмкость которого ограничена 500 записями — при переполнении старые записи вытесняются. Буфер сохраняется в `chrome.storage.local`.

В журнал записываются: статусы HTTP-ответов, перехваченные заголовки, курсоры пагинации и параметры GQL-запросов.

Панель отладки (доступна через иконку с жуком в шапке расширения) предоставляет кнопку **Скачать журналы**, которая экспортирует буфер в файл `twitch_scraper_debug_<timestamp>.txt`. Ведение журналов можно отключить для снижения потребления памяти браузера.

### 9.2 Экстренный сброс

Кнопка **Экстренный сброс** отправляет сигнал `full_reset` в `background.js`, который выполняет следующие действия:

1. Принудительно завершает все активные циклы `while` и `for`
2. Очищает все переменные состояния времени выполнения (`_isRunning`, `_shouldStopEnrich` и др.)
3. Сбрасывает объект `twitchHeaders` к значениям по умолчанию
4. Вызывает `chrome.storage.local.clear()`, удаляя все кэшированные данные, журналы и сохранённые настройки
5. Возвращает интерфейс в чистое состояние `idle`

Это обеспечивает надёжное восстановление при любом зависании или повреждении кэша расширения одним действием.
